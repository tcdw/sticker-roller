# Objective

Implement the local Bun HTTP API and production static-file serving boundary for the Web UI.

Do not modify `stickers/` or `stickers_archived/`.

## Requirements

- Use `Bun.serve()`, bind localhost by default, and do not expose secrets.
- Implement health, text asset CRUD/archive, job create/list/detail, cancel, retry-failed, and registered output routes.
- Validate JSON body, IDs, enum options, prompt/count/task limits, and content types; reject phase-1 reference image fields.
- Return `202` for accepted async jobs and a stable JSON error envelope.
- Serve output only if basename and database registry authorize it; never return filesystem absolute paths.
- Initialize/migrate SQLite and start the worker before listening.
- Make the handler testable without external network calls.

## Verification

Request-level tests must cover all routes, validation, output traversal protection, persistence across server handler recreation, and accepted jobs continuing through the worker. Run `bun test`, typecheck, and a Bun production smoke start if practical.
