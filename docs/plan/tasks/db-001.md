# Objective

Implement the durable database foundation for the Web UI. Use Drizzle ORM with `bun:sqlite`; do not use another SQLite driver. Add schema/migrations and repositories for text assets, durable jobs, generation items, LLM requests, generated files, and job events.

## Context

- `docs/INDEX.md`
- `docs/web/README.md`
- `docs/plan/analysis/web-ui.md`
- Existing generation options/constants in `src/config.ts` and `src/generator.ts`.

## Path

- `src/db/**`
- `src/web-types.ts`
- `drizzle.config.ts`
- `drizzle/**`
- `package.json`
- `README.md` only if database commands need documenting
- `docs/plan/tasks/db-001.md`

Do not modify `stickers/` or `stickers_archived/`. Do not implement filesystem data import.

## Requirements

- Support an injected/temporary database path for tests.
- Expose migration/init and close helpers.
- Use UTC timestamps in a consistent serializable format.
- Repository methods must include asset CRUD/archive, job creation with item rows/events, atomic queue claim, item/request transitions, file registration, job listing/detail, cancel and retry-failed, and startup recovery.
- Enforce foreign keys and uniqueness in schema where appropriate.
- Never store absolute output paths or credentials.
- Keep public types suitable for API and UI reuse.

## Verification

Run `bun test` for database tests and a TypeScript check. Tests must prove a fresh database can migrate, data survives closing/reopening, job snapshots are immutable, success/failure counters are consistent, retry does not rerun successful items, and stale running work is recoverable.
