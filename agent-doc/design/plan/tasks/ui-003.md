# Objective

Three workflow gaps made repeated generation slow: every new job started from an empty form, uploaded
images could be silently dropped from a job, and submitting wiped the whole toolbar.

## Requirements

1. **One-click reuse.** Each history job offers a single action that restores its authored prompt,
   generation options (model, aspect ratio, image size, remove background, count), and reference images.
   Each generated result can additionally be turned into a reusable image material and inserted into the
   current prompt as a reference.
2. **Unreferenced image warning.** When uploaded images exist that the prompt does not reference, submit
   asks for confirmation instead of silently generating without them.
3. **Non-destructive submit.** After a job is submitted, only the prompt input is cleared; the model,
   aspect ratio, image size, count, remove-background flag, and uploaded images stay as they were.

## Design notes

- Reuse is derived, not stored: `optionsFromSnapshot` rebuilds the current option shape from a persisted
  snapshot and drops values the app no longer supports, so old jobs stay reusable after a model changes.
- Reuse overwrites the composer, so it asks first whenever the composer is in use and the incoming prompt
  or generation settings differ; an untouched composer applies in one click.
- Reference images that were archived since the job ran cannot be resolved on submit; their tokens are
  stripped from the restored prompt and the removal is reported in the result notice.
- The unreferenced list is computed with the same `referencedImageIdsFromPrompt` parser used for
  submission, so the warning cannot disagree with what the job would actually send.
