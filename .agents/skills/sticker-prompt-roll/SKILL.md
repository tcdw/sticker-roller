# 贴纸提示词迭代

用 `bun run cli` 跑生成，看图，只改一处提示词，再跑。目标是让用户最终拿到能反复复现的提示词，而不是一次性碰运气。

## 先拿当前接口，别背参数

```bash
bun run cli -- help --json
```

一次读完命令、参数、枚举取值、默认值和退出码。**不要**记本文没写的 flag——CLI 的 help 才是唯一真相源。

## 流程

1. **查素材再引用。** 引用素材前先看清楚它到底写了什么：

   ```bash
   bun run cli -- asset list --search <关键词> --json
   bun run cli -- asset show <名字或 id> --json
   ```

   参考资料图同样先 `image list --json`，需要看时再 `image show <名字> --out /tmp/<名字>.png`。
   素材名只是引用键，凭名字猜内容会引用错东西。

2. **打草稿用便宜档。** 首轮建议 `--count 1` 加最便宜的模型和最小尺寸：每次生成都真花钱，一行命令就是一次真实调用。

3. **只从 stdout 取结果。** 生成命令的 stdout 只有图片绝对路径（一行一张），其余全是 stderr 的进度与错误。不要从混合输出里正则抠路径。

4. **看图验收。** 把路径交给图像读取工具（本环境是 `dim image read <path> --prompt "<逐条对照的问题>"`），对着本轮的验收点逐条检查，再决定改哪一句。

5. **单变量迭代。** 一轮只改提示词里的一处，否则无法归因；改动写进最终 prompt，不要留在命令行草稿里丢掉。

6. **定稿再上好档。** 结构定下来之后再用更好的模型、更大的尺寸和更多张数出最终版本。

## 退出码决定下一步

按 `help --json` 里的 `exitCodes` 分流，不要凭记忆：

- 成功：继续。
- **用法错误**（参数写错、引用了不存在或有歧义的素材/图片）：改命令行后重跑。CLI 会给出候选列表，从候选里挑准确的那个；**不要**退化成模糊名字反复试。
- **运行时错误**：数据库或 provider 的问题，不是提示词的问题，别改提示词。
- **有 item 失败**：成功的那几张照样在 stdout 里，可以先看图再决定要不要补跑。

## 边界

- 素材库和 `stickers/` 里的风格约束是唯一真相源，本 skill 不复制、不改写它们；需要改风格时改素材本身。
- 生成的任务会写进 web 的任务历史，用户在界面上看得到；不要为了试验反复刷大量任务。
- 提示词里的 `@[名字](asset:...)` 与 `![名字](image:...)` 语义由 CLI 解析并规范成 id，写人能读的名字即可。
